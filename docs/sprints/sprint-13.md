## Sprint 13: YouTube配信フローの統合テスト・エラーハンドリング・エッジケース対応

### 実装する機能

- **エンドツーエンド配信フロー統合**: Sprint 10-12で実装した各コンポーネント（認証→設定→配信作成→RTMP接続→ライフサイクル管理→停止）をカメラ画面の配信ボタンから一気通貫で実行できるフローとして統合する。YouTube配信先を選択した状態でカメラ画面の配信ボタンを押すだけで全工程が自動実行される。

- **エラーハンドリング強化**: ネットワーク切断、APIクォータ超過、トークン失効、配信枠の重複など、実運用で発生しうるエラーシナリオに対する包括的なハンドリングとリカバリーフローを実装する。

- **既存機能との共存確認**: YouTube API配信と手動RTMP配信（Twitch/カスタム）の共存を保証する。どちらのフローも選択・実行でき、互いに干渉しない。

### スプリント契約（完了条件）
以下の全条件を満たした場合のみ、このスプリントは完了とする。

#### エンドツーエンド配信フロー
- [ ] YouTube API連携の配信先を選択した状態で、カメラ画面の配信開始ボタンを押すと、API経由でbroadcast/stream作成→RTMP自動接続→配信開始まで自動で進む
- [ ] 配信開始中（API呼び出し〜RTMP接続完了まで）はローディング表示があり、ユーザーに進行状況が伝わる
- [ ] 配信中は既存のライブバッジ・経過時間・停止ボタンが表示される
- [ ] 配信停止ボタンを押すと確認ダイアログが表示され、確認後にRTMP切断→broadcastのcomplete遷移まで自動で行われる

#### エラーハンドリング
- [ ] 未ログイン状態でYouTube配信を開始しようとすると、「Googleアカウントにログインしてください」というメッセージが表示される
- [ ] YouTube配信作成中にネットワークエラーが発生した場合、「ネットワーク接続を確認してください」等のメッセージが表示され、配信は開始されない
- [ ] APIクォータ超過時に、「YouTube APIの利用制限に達しました。しばらくしてから再度お試しください」等のメッセージが表示される
- [ ] アクセストークンが失効し、リフレッシュにも失敗した場合、「再ログインが必要です」のメッセージと共にログイン画面への導線が提示される
- [ ] RTMP接続後にbroadcastのtesting→live遷移が失敗した場合、エラーメッセージが表示されるがRTMP接続は維持される（リトライ可能な状態）

#### 既存機能との共存
- [ ] 手動RTMP配信先（Twitch/カスタムRTMP）を選択した状態で配信開始すると、従来通りRTMP URLとストリームキーで直接接続される（YouTube APIフローは実行されない）
- [ ] YouTube API配信先と手動RTMP配信先を切り替えて、それぞれで配信開始・停止ができる
- [ ] 既存の手動RTMP配信先の追加・編集・削除が正常に動作する
- [ ] 録画中にYouTube配信を開始しようとすると、「録画中は配信を開始できません」のメッセージが表示される（既存の排他制御が維持される）

#### バックグラウンド・ライフサイクル
- [ ] YouTube配信中にアプリがバックグラウンドに移行すると、RTMP配信が停止し、broadcastステータスがcompleteに遷移する
- [ ] バックグラウンド移行による配信停止後、フォアグラウンド復帰時にstreamingStateがidleに正しくリセットされている
