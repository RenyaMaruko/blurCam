# Sprint 7: RTMP配信エンジンの基盤構築

## 目的

HaishinKitを導入し、VideoFrameProcessorから出力される処理済みPixelBufferをRTMPストリームとして送出できる配信エンジンを構築する。このスプリントではUIは最小限とし、配信の開始・停止が動作する技術基盤を完成させる。

## 実装する機能

- **HaishinKit導入と配信サービス（F14）**: HaishinKitをSPMで導入し、RTMP接続・切断、映像・音声の送出を管理する配信サービスを実装する。VideoFrameProcessorの `onProcessedPixelBuffer` コールバックから受け取るブラー処理済みPixelBufferを配信入力に渡す
- **配信音声キャプチャ（F17）**: 既存の `onAudioSampleBuffer` コールバックを活用し、マイク音声を配信ストリームに含める。映像と音声が同期した状態で送出する
- **配信操作の最小UI（F16の一部）**: カメラ画面に配信開始・停止ボタンを追加し、配信中であることが視覚的にわかる最小限のインジケーターを表示する

## スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

### HaishinKit導入

- [ ] HaishinKitがSwift Package Managerで導入されており、ビルドが成功する
- [ ] 配信サービスクラスが作成されており、RTMP URLとストリームキーを受け取って接続できる

### 配信の開始と停止

- [ ] RTMP URLとストリームキーを指定して配信を開始できる（テスト時はハードコードまたは設定画面から入力した値を使用）
- [ ] 配信を開始すると、指定したRTMPサーバーに接続され、ブラー処理済みの映像が送出される
- [ ] 配信中にカメラプレビュー画面で停止操作を行うと、RTMPサーバーとの接続が切断される
- [ ] 配信停止後に再度配信を開始できる（再接続が正常に動作する）

### 映像と音声

- [ ] 配信される映像にはブラー処理が適用されている（登録済み顔はクリア、未登録顔はブラー）
- [ ] 配信される映像にマイク音声が含まれている
- [ ] 配信中もカメラプレビューが滑らかに表示される（配信処理によってプレビューが明らかにカクつかない）

### 配信操作UI（最小構成）

- [ ] カメラ画面に配信を開始するためのボタンが表示されている
- [ ] 配信開始ボタンをタップすると配信が開始される
- [ ] 配信中は「LIVE」等の配信状態インジケーターが画面上に表示される
- [ ] 配信中は配信を停止するためのボタンが表示されている
- [ ] 停止ボタンをタップすると配信が停止され、インジケーターが消える

### エラーハンドリング

- [ ] RTMP URLが未設定の状態で配信開始ボタンをタップすると、設定を促すメッセージが表示される
- [ ] RTMP接続に失敗した場合（URLが不正、サーバー到達不可など）、エラーメッセージが画面に表示される
- [ ] 配信中にネットワーク接続が切断された場合、配信状態が自動的に「停止」に更新される

### 既存機能の維持

- [ ] 配信を行っていない状態で、写真撮影（ブラー適用済み）が正常に動作する
- [ ] 配信を行っていない状態で、動画撮影（ブラー適用済み）が正常に動作する
- [ ] カメラ切替・フラッシュ・メディアプレビュー・ズームが正常に動作する
- [ ] 設定画面の顔管理・ブラー強度設定が正常に動作する
