# Sprint 2: オンボーディングと顔登録

## 目的

初回起動時のオンボーディングフローを構築し、ユーザーの顔を登録できるようにする。顔登録はアプリのコア機能の前提条件であり、「あなたの顔を登録します」というシンプルなフローで、1画面1目的の原則に従って設計する。

## 実装する機能

- **ウェルカム画面**: アプリの目的を簡潔に伝え、顔登録フローへ誘導する
- **顔キャプチャ画面（F1）**: フロントカメラでユーザーの正面の顔を撮影し、顔データを端末内に保存する
- **登録完了画面**: 登録が完了したことを伝え、「これ以降、あなた以外は自動保護されます」と案内してカメラ画面へ遷移する

## スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

### ウェルカム画面

- [ ] 顔が未登録の状態でアプリを起動すると、カメラ画面ではなくウェルカム画面が表示される
- [ ] ウェルカム画面にアプリの目的を伝えるテキスト（プライバシー保護に関する説明）が表示される
- [ ] 「顔を登録する」ボタンが表示され、タップすると顔キャプチャ画面に遷移する
- [ ] ウェルカム画面は1画面で完結しており、スクロールが不要である

### 顔キャプチャ画面

- [ ] フロントカメラが起動し、ユーザーの顔がリアルタイムでプレビュー表示される
- [ ] 画面内に顔を合わせるためのガイド（丸枠やフレーム）が表示される
- [ ] 顔が検出されている状態で撮影ボタンをタップすると、顔データが保存される
- [ ] 顔が検出されていない状態では、撮影ボタンが無効化されているか、「顔をフレーム内に合わせてください」等のガイダンスが表示される
- [ ] 顔データは端末内（ローカルストレージ）にのみ保存され、外部に送信されない

### 登録完了画面

- [ ] 顔の登録が完了すると、完了画面が表示される
- [ ] 「あなた以外は自動保護されます」等のプライバシー保護が有効になることを伝えるメッセージが表示される
- [ ] 「はじめる」ボタンをタップすると、カメラプレビュー画面に遷移する

### フロー全体

- [ ] ウェルカム → 顔キャプチャ → 完了 → カメラ画面、の順に遷移が正しく動作する
- [ ] 顔登録済みの状態でアプリを再起動すると、オンボーディングをスキップしてカメラ画面が直接表示される
- [ ] オンボーディング中に顔キャプチャ画面で「戻る」操作をすると、ウェルカム画面に戻れる
